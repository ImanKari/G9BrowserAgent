Updated from v1 → v2

This extension is Engine 1 of G9: your AI agents drive the tabs of this browser — your sign-ins, your pages — through the local G9 daemon. For runs that should not tie up your screen, the daemon launches its own browser in the background (Engine 2). Both run the same tools.

Set up — three steps

  1. Install G9 Desktop

    Run G9-Setup.exe once — per user, no admin rights. Its wizard picks the browser for background runs (your Edge or Chrome, or it downloads Chrome for Testing), opens the automation profile once so you can sign in, applies the recommended browser policies (listed, with an undo), and registers G9 with the AI clients it finds.

  2. Add this extension — done

    You are reading this, so it is loaded. For the record: Developer mode → Load unpacked → paste the folder path the wizard copied to your clipboard. Leave that folder where it is: the extension's id comes from its path, and G9 Desktop updates it in place. On managed machines a policy installs it instead.

  3. Open your AI client

    Ask it to call browser_status. It answers — and everything else is the agent's job.

or click the G9 icon in the toolbar at any time.

What changed in v2

No modes

An agent takes the tab it works on with its first action — there is nothing to attach first. Workspace, Pinned, Follow and Multi are gone, and so is the allowlist.

One daemon, many agents

Any number of AI agents connect at once. Each tab has one owner at a time, and the panel shows who owns what.

Human input

Direct, Human or Stealth: curved mouse paths, real click timing and typing rhythm, set in the panel.

Pop out tab

Keeps a page alive in its own window while you work elsewhere. The panel offers it the moment an agent is blocked by a hidden tab. The one rule: do not minimise that window.

Send to background

Continues a tab in a browser G9 launches. The page reloads there with its cookies and storage; unsaved in-page state stays behind.

Record from now

Console and network are recorded from an agent's first action. To have them from earlier — the page load included — press Record from now in the panel. Auto-attach can do it for your project's sites.

The version, everywhere

In the panel header, the panel window's title and its About tab — so after a reload you can see at a glance which build is running.

Without G9 Desktop (developer setup)

Point your MCP client at the shim in a clone of the repository. It starts the daemon on 127.0.0.1:8765 when it needs it.

{
  "mcpServers": {
    "g9-browser": {
      "command": "node",
      "args": ["<path to the repo>/mcp/shim.mjs"]
    }
  }
}

Coming from v1? The bridge is replaced by the daemon. Old MCP configs that point at bridge/src/server.js keep working — it now forwards to the shim. If a v1 bridge is still running on port 8765, the panel says so and does not connect to it; close the editor or AI client that started it.

Always in your hands: everything an agent does is listed live in the panel's activity log, and Stop halts every agent at once — in this browser and in the background.
